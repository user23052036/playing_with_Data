# 3. Basic DML examples (INSERT / SELECT / UPDATE / DELETE)

Insert multiple rows:

```sql
INSERT INTO person (id, name, city)
VALUES
(101, 'sonu', 'molisio'),
(102, 'minu', 'pita'),
(103, 'kushi', 'rabada');
-- psql feedback: INSERT 0 3
```

Select all records:

```sql
SELECT * FROM person;
```

Update:

```sql
UPDATE person
SET city = 'rabdi'
WHERE id = 102;
-- psql feedback: UPDATE 1
```

Delete:

```sql
DELETE FROM person
WHERE id = 101;
-- psql feedback: DELETE 1
```

**Warning:** `UPDATE` or `DELETE` **without WHERE** affects all rows.

# 4. Column defaults, autogenerated IDs, and identity vs serial

### Best practice (PostgreSQL 10+)

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY;
```

* `INTEGER` — 4-byte signed integer (no `INTEGER(n)` or `INT(n)` in Postgres).
* `GENERATED BY DEFAULT AS IDENTITY` — SQL-standard auto-increment **that allows** manual inserts.
* `GENERATED ALWAYS AS IDENTITY` — SQL-standard auto-increment **that blocks** manual insertion unless overridden.
* `SERIAL` is older (still supported) — it creates a sequence + default value; prefer `IDENTITY`.

Examples:

```sql
-- old style
id SERIAL PRIMARY KEY

-- modern standard style
id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

### Note on manual inserts

With `BY DEFAULT` you can insert `id = 10` manually. With `ALWAYS` you cannot (unless special override).

# 5. Constraints — definitions, examples, and how they interact

**PRIMARY KEY**

* Uniquely identifies each row.
* Implies `NOT NULL` and is indexed.
* Only one primary key per table.

**NOT NULL**

* Column must have a value.

**UNIQUE**

* Ensures distinct values in a column (multiple UNIQUE columns allowed).

**DEFAULT**

* Supplies a value when none is given in `INSERT`.

**FOREIGN KEY**

* Ensures referential integrity — references a `PRIMARY KEY` or `UNIQUE` column in the parent table.

**SERIAL / IDENTITY**

* `SERIAL` (old) => integer + sequence + default nextval
* `IDENTITY` (modern) => follows SQL standard

**Example table using many constraints:**

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    age INTEGER NOT NULL,
    country VARCHAR(50) DEFAULT 'India'
);
```

# 7. Identity, primary key, foreign key — differences and step-by-step parent/child creation

**Important distinction:**

* `IDENTITY` = auto-number generator only.
* `PRIMARY KEY` = uniqueness + not null + index.
* `FOREIGN KEY` = references a `PRIMARY KEY` or `UNIQUE` on parent table.

Common error: creating a child table referencing a parent column that is not `PRIMARY KEY`/`UNIQUE`. You must make the parent column PK/UNIQUE first.

**Recommended steps to make a working parent/child relationship:**

1. Create parent table (even if minimal):

```sql
CREATE TABLE department (
    deptid INT,
    deptname VARCHAR(50)
);
```

2. Make the parent PK (cannot be NULL):

```sql
ALTER TABLE department
ALTER COLUMN deptid SET NOT NULL;

ALTER TABLE department
ADD PRIMARY KEY (deptid);
```

3. Add identity if you want auto-increment:

```sql
ALTER TABLE department
ALTER COLUMN deptid ADD GENERATED ALWAYS AS IDENTITY;
```

4. Create child table that references the parent:

```sql
CREATE TABLE doctor (
    doctor_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100),
    dept_id INT,
    CONSTRAINT fk_department FOREIGN KEY (dept_id)
      REFERENCES department (deptid)
);
```

This will succeed only when `department.deptid` is `PRIMARY KEY` or `UNIQUE`.

# 8. Common gotchas & practical notes (collected from your file)

* PostgreSQL does **not** support `INTEGER(n)` or `INT(n)` — using those will error.
* Forgetting `;` in `psql` triggers multiline prompt `dbname-#` — cancel with `Ctrl+C`.
* Use `GENERATED ... AS IDENTITY` (modern) instead of `SERIAL`. Behavior difference: `BY DEFAULT` vs `ALWAYS`.
* `IDENTITY` alone does not make the column `PRIMARY KEY`. You must add PK constraint separately.
* If you need to reference a parent column, ensure it is `PRIMARY KEY` or `UNIQUE` first.
* `SERIAL` vs `IDENTITY`: `SERIAL` creates a sequence and a default, `IDENTITY` adheres to SQL standard.

# 9. Quick cheat-sheet (one-page skim)
