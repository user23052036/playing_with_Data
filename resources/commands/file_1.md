**PostgreSQL Statement Execution Rule**

* Every SQL statement must end with `;`

* If you forget `;`, `psql` enters multiline mode and prompt changes to:

  ```
  dbname-#
  ```

  This means the statement is incomplete.

* To cancel an incomplete command:

  ```
  Ctrl + C
  ```

**Key Concept:**
PostgreSQL does not execute a statement until it sees a semicolon (`;`).

**PostgreSQL INTEGER Length Note**

* PostgreSQL does **not** support `INTEGER(n)` or `INT(n)`.
* Writing `INTEGER(10)` will cause an error.
* `INT` and `INTEGER` are the same (4-byte signed integer).
* Unlike MySQL, PostgreSQL does not use display width for integers.

Correct usage:

```
id INTEGER
```

## 1️⃣ What This Means

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY;
```

### `INTEGER`

Data type.

* `INTEGER` = 4-byte signed integer
* Range: −2,147,483,648 to 2,147,483,647
* `INT` and `INTEGER` are exactly the same in PostgreSQL.

So yes:

```sql
INT = INTEGER
```

---

### `GENERATED BY DEFAULT AS IDENTITY`

This is PostgreSQL’s modern auto-increment mechanism.

It means:

* PostgreSQL automatically generates sequential numbers.
* But **you are allowed to manually insert a value if you want.**

Example:

```sql
INSERT INTO users (id, name) VALUES (10, 'Souvik');
```

This will work.

If you had used:

```sql
GENERATED ALWAYS AS IDENTITY
```

Then manual insertion would fail unless you override it explicitly.

---

### `PRIMARY KEY`

This enforces:

1. Unique values
2. Not NULL
3. Automatically creates an index

So this column:

* Auto-increments
* Cannot be NULL
* Must be unique

---

## 2️⃣ Is `INTEGER` Same as `NUMBER` in MySQL?

No. Different concept.

### In PostgreSQL:

There is **no `NUMBER` type**.

PostgreSQL uses:

* `INTEGER`
* `BIGINT`
* `SMALLINT`
* `NUMERIC`
* `REAL`
* `DOUBLE PRECISION`

---

### In MySQL:

MySQL does **NOT** have `NUMBER` either.

It has:

* `INT`
* `BIGINT`
* `DECIMAL`
* `FLOAT`
* `DOUBLE`

`NUMBER` is actually an Oracle data type.

---

## 3️⃣ So What’s The Equivalent?

If you're thinking:

> “Is INTEGER like a numeric number type?”

No.

* `INTEGER` = whole numbers only
* `NUMERIC` / `DECIMAL` = precise decimal numbers (like 10.25)

Example:

```sql
price NUMERIC(10,2)
```

Means total 10 digits, 2 after decimal.

## 4️⃣ Modern PostgreSQL Best Practice

Instead of old:

```sql
id SERIAL PRIMARY KEY
```

Modern PostgreSQL (v10+) recommends:

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

Because it follows SQL standard.

### 1️⃣ Select All Records

```sql
SELECT * FROM person;
```

**Note:**

* `SELECT` retrieves data from a table.
* `*` means all columns.
* Returns all rows from `person`.

---

### 2️⃣ Update a Record

```sql
UPDATE person
SET city = 'rabdi'
WHERE id = 102;
```

**Note:**

* `UPDATE` modifies existing records.
* `SET` specifies the column to change.
* `WHERE` filters which row(s) to update.
* `UPDATE 1` → 1 row affected.
* ⚠ Without `WHERE`, all rows would be updated.

---

### 3️⃣ Delete a Record

```sql

WHERE id = 101;
```

**Note:**

* `DELETE` removes rows from a table.
* `WHERE` specifies which row(s) to delete.
* `DELETE 1` → 1 row removed.
* ⚠ Without `WHERE`, all rows would be deleted.

CREATE TABLE users (

    email VARCHAR(100) UNIQUE NOT NULL,
    age INTEGER NOT NULL,
    country VARCHAR(50) DEFAULT 'India'

## Short Explanation of Each Constraint

### 1️⃣ PRIMARY KEY

* Uniquely identifies each row.
* Automatically enforces:

  * `UNIQUE`
  * `NOT NULL`
* Only one primary key per table.
* Creates an index automatically.

Example:

```sql
id SERIAL PRIMARY KEY
```

---

### 2️⃣ NOT NULL

* Ensures a column cannot store `NULL`.
* Value must be provided during insert.

Example:

```sql
username VARCHAR(50) NOT NULL
```

---

### 3️⃣ DEFAULT

* Provides a default value if none is supplied during insert.

Example:

```sql
country VARCHAR(50) DEFAULT 'India'
```

If country is not given, it becomes `'India'`.

---

### 4️⃣ SERIAL (auto_increment)

* Auto-increment integer.
* Internally creates:

  * Integer column
  * Sequence
  * Default next value from sequence
* Older PostgreSQL style (modern alternative: `GENERATED AS IDENTITY`).

Example:

```sql
id SERIAL
```

---

### 5️⃣ UNIQUE

* Ensures all values in that column are distinct.
* Allows multiple UNIQUE columns in a table.
* Unlike primary key, can allow NULL (but only one NULL per column in PostgreSQL versions before 15 behavior change).

Example:

```sql
email VARCHAR(100) UNIQUE
```

---

## Quick Summary (For Notes)

* **PRIMARY KEY** → Unique + Not Null + Indexed
* **NOT NULL** → Value required
* **DEFAULT** → Auto value if none provided
* **SERIAL** → Auto-increment integer
* **UNIQUE** → No duplicate values allowed
